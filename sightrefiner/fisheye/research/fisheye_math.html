1. 为什么鱼眼不能是针孔：曲率的刚性障碍

所有相机做的都是同一件事：把射线方向空间映射到平面。方向空间是单位球面 S² （更严格地说，是射影空间，但对前向半球可以用球面代表）。所以任何相机模型本质上是一个映射 Π : U ⊂ S² → ℝ²。

针孔相机取 U = 开半球，Π 是中心投影（gnomonic）。它的关键性质是把大圆映射成直线， 因此保持共线性、保持交比，这正是射影几何可以介入的原因。代价是 ρ = f tan θ：当 θ → 90° 时 ρ → ∞。 所以针孔模型的 FOV 严格小于 180°，而且接近 180° 时像面尺寸爆炸。180° 视场在针孔模型下不是"精度不够"，而是不存在。

那么能不能找一个"没有畸变"的 180° 映射？这里"没有畸变"如果理解成等距（isometry，保持所有测地距离）， 答案是确定的否。由高斯绝妙定理（Theorema Egregium），等距映射保持高斯曲率；球面 K = 1/R² > 0， 平面 K = 0，故不存在等距映射，哪怕局部也不存在。

(1.1) 球面度量   ds² = dθ² + sin²θ · dφ² 任何平面化都必须破坏这个度量中的某一部分——这不是工程缺陷，是几何事实

所以"鱼眼矫正"这个说法本身需要澄清：我们不是在消除畸变，而是在选择把畸变放在哪里。 可选的取舍互斥（这是地图投影两百年来的老问题）：

保持什么 牺牲什么 对应投影 本项目用途
共线性（直线→直线） FOV 有界 <180°，边缘面积爆炸 gnomonic（针孔） 四路虚拟透视
角度（保角/共形） 面积严重不均 stereographic 未使用
面积（等积） 形状剪切 equisolid 未使用
径向角距离 切向拉伸随 θ 增长 equidistant 传感器侧模型
方位角均匀性 天顶方向被拉成线 cylindrical equiangular 全景展开

本项目的整个架构就是这张表的直接后果：用 equidistant 描述镜头实际做了什么， 再用 gnomonic 或 cylindrical 描述我们希望下游看到什么，两者通过球面这个公共中介连接。

2. 投影族与本项目的模型选择

旋转对称镜头的畸变完全由一个一元函数 ρ(θ) 刻画（ρ 为像高，θ 为入射角）。 常见的闭式族：

(2.1) equidistant: ρ = f θ   ·   equisolid: ρ = 2f sin(θ/2)   ·   stereographic: ρ = 2f tan(θ/2)   ·   orthographic: ρ = f sin θ

这些径向函数可用奇次 Taylor 级数表示，并用 Kannala–Brandt 形式的有限奇次多项式近似。cv2.fisheye 使用角度的有限奇次多项式模型；有限截断并不与每个闭式投影族完全相等。本项目只使用一阶项 ρ=fθ，即 equidistant。

model.py 中的标定关系是纯几何的：成像圆边缘对应 θ = θmax = fov/2， 该处像高等于圆半径 R，代入 ρ = fθ 得

(2.2) f = R / θmax   ⟹   R = 930 px, fov = 180°  ⟹  f = 930/(π/2) = 592.06 px/rad = 10.33 px/deg

equidistant 的内在各向异性。 这一点值得单独算清楚，因为它决定了矫正质量的理论上限。 像面上的径向线元是 f dθ，切向线元是 f θ dφ； 而球面上对应的是 dθ 与 sin θ dφ。因此切向/径向的相对拉伸为

(2.3) σ(θ) = θ / sin θ   =   1 + θ²/6 + 7θ⁴/360 + O(θ⁶) θ=30°: +4.7% · θ=45°: +11.1% · θ=60°: +20.9% · θ=75°: +35.5% · θ=85°: +48.9% · θ=90°: +57.1%

σ 也正是像面面元与球面立体角之比：dA = f²σ(θ) dΩ。 它的含义是：传感器把边缘的立体角"过采样"了 ——θ=85° 处每单位立体角占用的像素比天顶多 49%。 重映射可以改变输出像素密度，但不能增加已采集的信息；最终在哪个方向压缩、是否模糊，还取决于输出投影和分辨率，需检查复合映射的雅可比（§7）。

模型误配的代价（已量化）。 若真实镜头是 equisolid 而我们按 equidistant 反解角度， 由 θ̂ = (ρ/R)·θmax 得到的角度误差为： θ=30° → +2.94°，45° → +3.71°，60° → +3.64°，75° → +2.48°。连续区间内最大值为 +3.80°，位于 θ≈51.60°，由角度误差函数的导数为零求得。 误差在中场最大而非边缘最大，这与直觉相反，也与 fisheye_research.html 中 "误差集中在最终会被丢弃的边缘区"的说法不一致——按 (2.1) 归一化后两曲线在两端被强制重合， 差异必然集中在中间。equidistant 是本项目采用的默认假设，是否适合实际镜头仍需规格或标定数据验证；上述误差仅针对归一化后的 equisolid 示例，并非所有真实镜头的误差上界。

3. 单帧自动校准：能观测什么，不能观测什么

calibrate.py 从一帧图像估计 profile。这里需要先讨论可辨识性： 哪些参数真的被数据约束，哪些只是先验。

3.1 成像圆检测：Kasa 代数拟合

圆拟合的几何最小二乘 min Σ(√((xᵢ−cx)²+(yᵢ−cy)²) − r)² 是非线性的。Kasa 的技巧是改用代数残差，把问题线性化。令 c = r² − cx² − cy²，则圆方程 x²+y² = 2cxx + 2cyy + c 对未知量 (cx, cy, c) 是线性的：

(3.1) A = [ 2xᵢ   2yᵢ   1 ],    bᵢ = xᵢ² + yᵢ²,    (cx, cy, c)ᵀ = A+b,    r₀ = √(c + cx² + cy²) 对应 calibrate.py:48-51，一次 lstsq 直接闭式解出初值

代价是代数残差 ≈ (dᵢ−r)(dᵢ+r) ≈ 2r·(几何残差)， 权重随点到圆心距离变化，因此 Kasa 在只覆盖部分圆弧时有系统性偏置（半径偏小）。 这正是代码不止步于此的原因。

3.2 径向精化：把估计问题变成投票问题

calibrate.py:56-71 沿 360 条径线在 [0.7r₀, 1.3r₀] 上采样亮度剖面 I(s)，寻找满足两个条件的最外侧位置： I(s) − I(s+4) ≥ 15（足够的向外亮度跌落）且 I(s+4) < 30（跌入黑区）。 然后将跌落起点加 2 px，取这些过渡中点半径的中位数作为 r。

中位数的崩溃点约为 50%，指的是进入中位数计算的半径样本中，少于一半被任意污染时，估计不会被推到任意远处；这不保证无偏。“至少 60 条径线成功”的门槛只限制样本数，不能保证成功径线中有多少是真正边界，更不能保证全部 360 条径线中有 40% 被污染时仍然准确。圆心仍来自 Kasa 拟合，半径中位数无法纠正圆心的系统偏差。

与预处理参考值的一致性（2026-08-10_pilot_camera_scrnsht，60 个真实样本，R ∈ [97, 188] px）：
圆心差异中位数 0.54 px（p90 = 2.26，max = 5.05）；半径差异中位数 0.32 px（p90 = 0.89，max = 2.78）。
按每张图的焦距把圆心差异换算为等效角度后，中位数为 25.21 arcmin；半径相对差异中位数 0.236%，对应 θ=85° 处约 0.20° 的等效角度差异。60/60 全部成功，无 fallback。参考值由预处理脚本中的 Kasa 拟合和径向精化生成，与被测算法同源，并非独立 ground truth；这些数字不能证明绝对校准精度。
验证方法上的一个陷阱。另一批 2026-08-13_fisheye_setting_snapshots（6 样本，R ∈ [919, 1425]）的差异四舍五入后恒为 0.00 px。这是因为该批 preprocess.py:79 直接调用同一个 detect_image_circle() 生成参考值，属于循环验证。这些指标只能检查流程一致性，不能评估精度。两批样本都缺少独立精度验证，尤其不能把小半径截图上的一致性统计直接外推到约 1000 px 的生产分辨率。

3.3 FOV 的不可辨识性

calibrate.py 的 docstring 说没有场景假设时 FOV 无法从单帧观测。当前算法只提取成像圆几何 (cx, cy, R)，而 f 与 θmax 只通过 f·θmax = R 受约束。所有满足该式的参数都对应相同的成像圆，仅凭这个约束无法区分；已知场景直线等额外图像约束则可能打破歧义。

后果是：假设 fov = 180° 而真实为 190° 时，我们索取的角度与实际采样的角度之间存在一个全局线性重标定 θ真 = θ索取 · (fov真/fov假)：

索取 θ 实际采样 θ（真 fov=190°） 误差 h=3m 地面半径误差
30° 31.67° +1.67° +0.12 m
60° 63.33° +3.33° +0.78 m
85° 89.72° +4.72° +584.50 m

表中地面差异按 h[tan(θ真)−tan(θ索取)] 精确计算，假设无遮挡的无限地面；最后一行不代表门店的实际可见距离。局部灵敏度是 h/cos²θ（§9.1），接近 90° 时不能用一阶近似替代上式。fov_deg 因而需要保留为可编辑字段。要辨识 FOV，需要镜头规格、已知标定物、多帧运动或场景直线等额外约束。

4. 矫正 = 拉回：从射线到像素

实现上有一个容易被忽略但很关键的方向选择。朴素的想法是"把源像素推到目标位置"（forward warping）， 这会产生空洞和重叠，需要 splatting。代码采用的是逆向映射（backward warping）： 遍历输出像素，对每个输出像素问"它该从源图哪里取值"。

用数学语言说，这是把图像视为函数 I : ℝ² → ℝ³，构造 Π ∘ D 并计算拉回 (pullback) Iout = (Π ∘ D)*Isrc：

(4.1) (u,v)  —D→  d ∈ S²  —Π→  (mx, my)  ⟹  Iout(u,v) = Isrc(mx, my) D = projections.py 的 dirs_for_view；Π = model.py 的 rays_to_pixels；组合结果就是 LUT

这个分解是整个模块的架构支点。D 只依赖想要什么输出（视图定义）， Π 只依赖相机是什么（profile）。二者通过球面上的单位向量解耦， 所以增加一种新输出投影不需要碰相机模型，换一台相机不需要碰投影代码。

model.py:68-81 的 Π：

(4.2) θ = atan2(√(dx²+dy²), dz),    φ = atan2(dy, dx)
mx = cx + fθ cos φ,    my = cy + fθ sin φ
两个实现细节的数学理由。 用 atan2(hypot(dx,dy), dz) 而非 arccos(dz) 计算 θ：后者在 θ→0 处导数 −1/√(1−dz²) 发散，浮点误差被放大；atan2 形式在全域数值稳定。
超出 FOV 的射线（θ > θmax）被写成 (−1,−1) 而非 clamp 到边界： clamp 会把镜头外的方向伪造成边缘像素的复制，产生不存在的图像内容； (−1,−1) 落在源图外，由 BORDER_CONSTANT 填黑，让"无数据"在下游保持可识别。

5. 四个角度是怎么选的（及为什么不是 3 或 6）

DEFAULT_VIEWS 给出四路虚拟透视：azimuth ∈ {0°, 90°, 180°, 270°}，tilt = 50°，hfov = 90°， 尺寸 480×360（4:3）。projections.py:24-34 构造对应的射线场：

(5.1) fp = (W/2) / tan(hfov/2),    n(u,v) = normalize( (u−W/2)/fp, (v−H/2)/fp, 1 )
d = Rz(azimuth) Rx(tilt) · n

注意旋转的顺序不可交换：先 Rx 把视轴从光轴（天底方向）抬起 tilt， 再 Rz 绕光轴旋到指定方位。反过来做会得到一族错误的视轴。 这个顺序同时保证了"图像的上方指向远离天底的方向"，从而人在画面中直立。

5.1 方位角选择的判据

N 个均匀方位视图的间距为 360°/N。在给定 θ 上，只有当单视图覆盖的是一个连续方位区间时，区间宽度 σaz(θ) 不小于间距才是完整覆盖的判据。若覆盖分裂为多个区间，必须检查所有视图的区间并集，不能只比较总宽度或最外端点。

(5.2) 单连续区间时的覆盖条件：   σaz(θ) ≥ 360°/N

σaz(θ) 不是 θ 的单调函数。hfov=90°、tilt=50°、4:3 时，先将球面射线逆旋转为虚拟相机坐标 q，再检查 qz>0、|qx|≤qz、|qy|≤0.75qz。下表采用这个连续画幅边界；接近最外角时，上边界会使方位覆盖分裂为两段。

θ 单视图覆盖总宽度 与 90° 间距之差 状态
13.2° 12.0° −78.0° 四路下边缘中心附近开始覆盖，仍有大片空缺
≈18.26° 90.0° 0.0° 内边界：相邻区间接合
30° 132.3° +42.3° 与每个相邻视图重叠约 42.3°

上述配置的全方位覆盖带为 θ≈[18.26°, 75.57°]。边界可在相邻视轴的方位中线（偏角 45°）代入画幅不等式求得。这是当前配置的几何结果，并不证明四路配置对所有场景最优。

  • hfov 和视图数需要联合选择。4 × 90° = 360° 只是名义水平视场之和，不能替代球面覆盖计算。减少到三路会缩窄完整覆盖带；增加到六路会增加重叠与覆盖范围，在每路尺寸不变时，remap 的输出像素数增加 50%。检测成本还取决于模型及批处理方式。
  • tilt = 50° 决定带宽的位置。对 h=3 m 的顶装，完整覆盖带对应地面半径约 0.99–11.66 m；是否满足客流区域要求，需要对照现场布局和目标高度。
  • 4:3 的宽高比隐含了 vfov。vfov = 2 arctan(0.75) = 73.74°，对角 FOV = 102.68°。连续画幅覆盖 θ≈[13.13°, 87.56°]，最大极角在每路的两个上角达到。480×360 的像素中心实际采样范围约为 [13.21°, 87.50°]，应与连续边界区分。

6. 盲区：立体角的精确记账

用户关心"裁剪后有没有盲区"。答案是有，而且可以精确算出来。 在半球上以 sin θ dθ dφ 为测度做数值积分（2000×2880 网格）， 统计每个方向被多少个视图覆盖：

区域 占半球立体角 说明
0 个视图（盲区） 9.70% 天底盲锥 + 边缘盲带
1 个视图 69.02% 有效单覆盖
2 个视图（重叠） 21.28% 同一目标被采样两次
3 个及以上 0.00% 不存在三重覆盖
四视图立体角之和 = 111.58% 半球；重复采样占总采样立体角 21.28/111.58 ≈ 19.07%

盲区按近场与远场分账；近场还包括盲锥外的部分方位缺口：

  1. 近场盲区 θ<18.26°，占半球立体角约 3.29%。其中 θ<13.13° 是完全不可见的天底盲锥，占 2.61%；13.13°–18.26° 之间另有约 0.67% 的部分方位缺口。完全盲锥来自 50°−arctan(0.75)，h=3 m 时对应半径 0.70 m、面积 1.54 m²；h=4 m 时半径 0.93 m、面积 2.73 m²。这些方向在原始鱼眼图上有像素，只是当前四路视图未取样。
  2. 远场盲区 θ>75.57°，占半球立体角约 6.41%。方位缺口逐渐张开，超过约 86.87° 后每路覆盖分裂为两段，θ>87.56° 完全无覆盖。h=3 m 时，θ=80°、85°、87.5° 分别对应地面半径 17.0 m、34.3 m、68.7 m；是否可以舍弃这些区域需结合现场范围判断。
21.28% 的重叠是一个尚未处理的功能性问题。 四路视图是对同一颗球面独立重采样的结果，落在重叠区的目标会在两个视图里各出现一次。 用于客流计数时这直接导致重复计数。数学上重叠区是精确已知的（就是上图的橙色扇形）， 因此存在干净的解法：把每个检测框的中心反投影回球面得到 (θ, φ)， 在球面坐标下做跨视图 NMS——球面是所有视图的公共参考系，这比在各自像面上做去重更自然。 当前 dewarp.py 只负责产出图像，代码库中没有这一步。

7. 采样率与雅可比：分辨率在哪里被浪费

复合映射的雅可比矩阵描述局部采样足迹。其行列式给出面积采样率，可闭式写出；两个奇异值分别给出两个主方向的尺度，判断抗锯齿需求还必须检查它们。

设 α 为像素方向与视轴的夹角，则针孔像面到球面的面元关系为 dΩ = cos³α · du dv / fp² （距离平方给出 cos²α，像面法向投影再给出一个 cosα）。 再用 dA = f²σ(θ) dΩ 复合：

(7.1) |J| = (f / fp)² · (θ / sin θ) · cos³α,    cos α = (1 + ũ² + ṽ²)−1/2 与数值微分逐点吻合，相对误差 < 4×10⁻⁶（7 个测点，含中心/边/角）

|J| 表示每个输出像素对应的源像素面积，是两个奇异值的乘积：

  • |J| > 1 时至少一个方向在抽取源信号，存在混叠风险。cv2.remap 的 INTER_LINEAR 只做局部双线性插值，不提供随缩小比例调整的抗锯齿预滤波，周期纹理可能出现摩尔纹。
  • |J| < 1 仅表示面积放大，不保证各方向都在放大，也不保证无混叠。例如奇异值为 2 和 0.25 时，行列式为 0.5，但一个方向仍在二倍抽取。需检查最大奇异值；只有两个方向都不抽取，才能排除局部缩小带来的额外混叠风险。

以下面积采样率可用于比较尺寸与成本，但不能单独作为无锯齿判据。两套配置的数值为：

8. 全景展开的度量性质与"接缝"的真相

panorama_dirs（projections.py:37-48）是等角柱面展开： 列线性对应方位角，行线性对应极角。

(8.1) φ(j) = φ₀ + 2π(j+½)/W,    θ(i) = θ₁ − (θ₁−θ₀)(i+½)/H
d = (sin θ cos φ,   sin θ sin φ,   cos θ)

行方向为什么是递减的。 这是顶装几何的一个反直觉之处，代码注释专门说明了它。 对 h=3 m、身高 1.7 m 的人，站在地面半径 d 处：脚的极角 θ脚 = arctan(d/h)，头的极角 θ头 = arctan(d/(h−1.7))。因为分母更小， 头的极角总是大于脚的极角：

地面距离 θ脚 θ头 θ头−θ脚
0.5 m 9.46° 21.04° +11.58°
2.0 m 33.69° 56.98° +23.29°
5.0 m 59.04° 75.43° +16.39°

所以要让人在全景图里头朝上，θ 必须沿行号递减。由像素中心采样约定，第 0 行接近上界 θ₁，末行接近下界 θ₀；例如 4184×639、theta_deg=[30,85] 时分别约为 84.96° 和 30.04°。方向写反会让站立行人在图中倒立，可能影响检测；具体影响需用检测数据评估。

8.1 角度方形像素

make_report.py:48-49 取 Wp = 4.5R、 Hp = Wp(θ₁−θ₀)/360°。 这不是随手选的宽高比——它使

(8.2) Δθ = (θ₁−θ₀)/Hp = 360°/Wp = Δφ 实测 R=930: 4184×639，Δφ=1.5017×10⁻³ rad，Δθ=1.5022×10⁻³ rad，比值 1.0003 ✓

即每个全景像素张开的角度是方的（5.16 arcmin × 5.16 arcmin）。 但这不代表内容各向同性——每个全景像素消耗的源像素为径向 fΔθ、 切向 f θ Δφ，比值恰为

(8.3) 源采样足迹的切向/径向比 ≈ θ [rad]；输出相对源图的切向/径向放大比 ≈ 1/θ 相对源图：θ=30°→1.91（切向拉伸）· θ=57.3°→1.00 · θ=85°→0.67（切向压缩）

θ≈1 rad 只表示相对于 equidistant 源图的局部尺度比接近 1，不表示真实场景形状在此处最忠实。若参照球面度量，等角全景的切向/径向放大比是 1/sinθ；若参照地面上的人或物体，还会受深度与高度影响。选取 theta_deg 区间需要同时考虑极点拉伸、掠射和现场覆盖：

配置 θ 区间 占半球立体角 理由
DEFAULT_VIEWS [20°, 80°] 76.60% 较宽，保留更多近场
make_report.py [30°, 85°] 77.89% 丢弃天顶拉丝(<30°)与极端掠射(>85°)

下界接近 0 会产生强烈拉伸：θ→0 时整个天底点被拉成一整行 Wp 个像素 （柱面投影在极点的经典奇性），产生"拉丝"。但代价是 θ₀ = 30° 在 h=3 m 时 对应地面半径 1.73 m，即全景图放弃了相机正下方 9.42 m² 的区域—— 比四路透视的盲锥（1.54 m²）大 6 倍。这是全景配置比四路透视更严重的近场盲区， 两者都不覆盖天底。

8.2 "接缝"：几何上不存在，语义上存在

fisheye_research.html 提到"0°/360° 接缝会切人"。这个说法需要精确化，因为它容易被误解为像素级不连续。 实测 (8.1) 的采样：φ[0] = 0.043021°，φ[W−1] = 359.956979°， 跨缝角距 = 0.086042°，而常规列间距 = 0.086042°——完全相等。

结论：射线映射在 φ 方向是光滑周期函数，0°/360° 不引入多相机拼接式的几何错位，因此不需要为了这条切缝做曝光补偿或 blending。源图的物体边缘及插值仍可能产生非光滑像素变化，不能据此保证离散图像处处 C¹ 连续。圆柱被剪成矩形后，跨越切缝的目标仍会分到图像两端，影响下游检测。

可采用以下两种处理方式：

  • 循环填充：把左侧 δ 列重复到右端，输出宽度为 Wp+δ。若在 LUT 中实现，式 (8.1) 的角度步长分母必须保持原周期宽度 Wp，只扩展列索引；直接把当前 panorama_dirs 的宽度改成 Wp+δ 只会重新采样一整圈，不会增加周期重叠。扩展 LUT 仍使用同一 remap 流程，但会增加内存与逐帧采样量；检测后还需在周期坐标下去重。
  • 旋转 φ₀：phi0_deg 已经是 profile 字段， 可按现场把接缝转到墙面/货架等无人区域。这是最省成本的做法，但依赖现场知识。

9. "拼接"这个词在本项目中不成立

这一点需要明确指出，因为它是理解本模块的关键，也直接回答"全景图怎么拼接"这个问题： 本项目不做任何拼接。

经典全景拼接（Brown & Lowe 式）的流程是：特征检测 → 匹配 → 估计单应/旋转 → bundle adjustment → 寻找最优缝（graph cut / dynamic programming）→ 曝光补偿 → 多频段融合。它之所以必要，是因为多个相机/多次拍摄之间的相对姿态未知， 必须从图像内容里估计出来，且不同曝光造成的亮度不连续必须融合掉。

本项目的处境完全不同：全景图与四路视图都来自同一颗光心、同一帧、同一次曝光。 所有输出射线的方向在标定完成后解析已知——就是 (5.1) 和 (8.1)。因此：

拼接流程中的步骤 本项目 数学原因
特征检测与匹配 不需要 对应关系由 (4.1) 闭式给出，不需要从内容估计
单应/旋转估计、BA 不需要 视图间旋转是我们自己指定的 RzRx，精确已知
接缝寻找 不需要 柱面展开精确周期（§8.2）；四路视图各自独立输出，不合成一张图
曝光补偿 / 多频段融合 不需要 同一次曝光、同一个 ISP，无亮度阶跃
视差处理 不需要 单一光心 ⟹ 视差恒为零，这是最本质的区别

单一光心这一条最关键。多相机拼接的根本困难在于光心不重合， 对不同深度的物体无法用同一个单应对齐（视差），只能靠 seam 与融合掩盖。 单光心情形下，从球面到任何输出面的映射是精确的坐标变换，与场景深度无关。 所以本项目的"全景"是一次重参数化（change of coordinates），不是拼接（registration + blending）。

四路视图同理，而且它们从不被合成为一张图。 Dewarper.process() 返回的是一个 dict，五路输出彼此独立、分别交给下游。 make_report.py:114-136 里的 np.hstack / np.vstack 只是为了生成人看的对比图，不是几何意义上的拼接。 §6 那 21.28% 的重叠也因此不会被"融合"掉，而是如实地重复出现在两路输出里。

什么时候才真的需要拼接？ 只有当需要把多台鱼眼相机的画面合到一个门店平面图上时。 那时候视差重新出现（不同相机光心不重合），并且需要外参（各相机在门店坐标系中的位姿）。 对这个场景，正确的做法不是拼图像，而是用 groundplane_dirs 把每台相机 独立映射到同一个地面坐标系，在度量空间而非像素空间做融合—— 因为地面这个共同平面把视差问题化归为单应，而且客流分析真正需要的是地面上的轨迹，不是好看的大图。

9.1 地面正射：唯一引入场景假设的投影

groundplane_dirs（projections.py:51-60）值得单独一提，因为它在数学性质上与前两者不同。 它构造 d ∝ (x, y, h)，即假定被观测点落在 z = h 的平面上。前两种投影是纯角度的重参数化，对任何场景都成立； 而这一种断言了深度，因此只对真正贴地的东西（地砖、地面标记、脚部）正确。

代价体现在度量灵敏度上。由 r = h tan θ 得 dr/dθ = h/cos²θ，随 θ 剧烈发散：

θ 地面半径 (h=3m) dr/dθ 固定 +3.71° 角度扰动的精确位置差
20° 1.09 m 3.40 m/rad 0.23 m
40° 2.52 m 5.11 m/rad 0.35 m
60° 5.20 m 12.00 m/rad 0.88 m
75° 11.20 m 44.78 m/rad 3.83 m

最后一列用 h[tan(θ+3.71°)−tanθ] 精确计算，展示同一角度扰动在不同位置的放大；不是 equisolid 在各角度的实际误差。一阶导数只适用于足够小的扰动。地面正射在远场对模型误配和 FOV 假设更敏感，可信范围取决于实际标定质量。离地物体还会有额外偏移：头部会被映射到脚部更远的位置。

10. 定点 LUT：量化误差与运行时代价

(4.1) 的复合映射对每个输出像素只依赖几何，与帧内容无关。因此可以在标定阶段 一次性求值并冻结成表。dewarp.py:18-25 调用 cv2.convertMaps(..., CV_16SC2) 把浮点坐标拆成定点表示：

(10.1) mx = nx + kx/32,    nx ∈ ℤ (int16),   kx ∈ {0,…,31} OpenCV INTER_BITS = 5 ⟹ 步长 2⁻⁵ = 1/32 px；每个坐标分量的最大量化误差 1/64 = 0.015625 px（四舍五入而非截断）

双线性权重被预先量化成 32×32 = 1024 种组合，存在 m2（uint16）里作为索引。 对于本项目常用的 uint8 图像，插值主要使用查表和定点乘加；浮点图像仍可能走浮点运算路径。

把沿径向的 0.015625 px 误差换算回角度（R=930）：

(10.2) Δθ = Δρ / f = 0.015625 / 592.06 = 2.64×10⁻⁵ rad = 5.44 arcsec

5.44 arcsec 是沿径向 1/64 px 扰动的等效角度。二维坐标都发生量化时，径向误差上界为 √2/64 px，对应约 7.70 arcsec。它仍远小于同一 R=930 下的单像素径向张角 5.81 arcmin。§3.2 的样本一致性统计来自不同分辨率且不是绝对精度，不能直接据此宣称量化误差比生产校准误差小 260 倍。

LUT 内存（按数组类型与尺寸核算，5 路输出）：

视图 m1 (int16×2) m2 (uint16) 合计
panorama 1280×384 1.97 MB 0.98 MB 2.95 MB
perspective 640×480 ×4 4.92 MB 2.46 MB 7.37 MB
总计 10.32 MB（float32 xy 需 13.76 MB）
成本模型的关键性质：每帧 remap 的像素工作量为 O(Σ 输出像素)。固定输出尺寸可以控制工作量，但输入大小仍会影响缓存与访存，不能保证 4K 和 1080p 的实测耗时相同。输出像素数增加会线性增加采样工作量；是否值得增加分辨率，应结合源采样尺度与下游任务判断。

12. 当前实现的数学缺口

需要结合下游任务评估的缺口：

  1. 跨视图重复计数未处理（§6）。21.28% 的立体角被两个视图同时覆盖， 落在其中的目标产生两次检测。球面坐标 (θ, φ) 下的跨视图 NMS 是自然解法， 目前代码库中不存在。直接累加各路检测会有重复计数风险，盲区与检测漏检也可能影响业务统计。
  2. DEFAULT_VIEWS 的尺寸与 R 解耦（§7）。固定 480×360 在 R=930 时中心面积采样率为 6.93，两个主方向都在抽取，可能产生混叠。应结合雅可比奇异值选择尺寸，并在缩小时使用预滤波/多尺度采样，或高分辨率 remap 后再以 cv2.resize(..., INTER_AREA) 缩小；直接给 remap 传 INTER_AREA 无效。报告配置已经按 R 缩放，但库默认值没有。
  3. 两批样本都缺少独立精度验证（§3.2）。小图参考值来自同源算法，大图参考值直接来自被测函数；现有指标说明流程一致性，不能给出绝对精度。需要人工标注、标定物或独立方法产生真值，并单独评估生产分辨率。
  4. 圆模型不能表达椭圆成像。裁切后的圆弧仍可属于同一个圆，当前代码已过滤画幅边界点；问题是弧段不足、污染和非圆成像会降低拟合可靠性。是否需要椭圆模型或更稳健的弧段拟合，应由实际样本验证，不能把裁切本身等同于圆模型失效。
  5. 当前默认及报告视图未覆盖天底盲区（§6、§8.1）。 四路透视放弃 θ<13.13°，全景（30° 下界）放弃 θ<30°， h=3 m 时分别是 1.54 m² 和 9.42 m²。原始鱼眼图在这里是有像素的， 只是当前配置没有视图去取；库提供的地面正射或新增天底视图可以覆盖。若正下方需要覆盖，加一路 tilt=0 的天底视图即可（LUT 成本固定，运行时增量线性）。
  6. 全景接缝的循环填充未实现（§8.2）。可以在烘焙 LUT 时扩展列数，运行时仍是同一 remap 流程，但新增列会增加内存与采样成本，也需要下游做周期坐标下的去重。
  7. 无光度学处理。实际鱼眼镜头可能存在渐晕，当前 pipeline 不做平场校正。相对照度取决于镜头投影、孔径、遮挡和 ISP，不能直接把针孔近似的 cos⁴θ 律当作鱼眼镜头的定量照度曲线；需要平场实测或镜头数据。
整体评价。Π ∘ D 的分解将相机模型与输出投影解耦，单光心下可以通过重参数化生成多种视图；LUT 量化误差相对像素采样间距很小。现有数据仍不足以确认绝对校准精度，且可编辑的 model 字段尚未连接到多模型实现。球面覆盖、盲区和采样尺度可以帮助下游选择视图与跨视图去重，但具体收益需要独立标定与任务评估验证。
